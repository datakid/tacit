# Decisions

The code has no comments (owner's rule). This file explains why things are the way they are.

1. **Plain `Activity` and platform widgets.** No AppCompat, Compose or RecyclerView: zero runtime dependencies means less class loading at cold start and a smaller heap, so Android kills the process less often. `ListView` with recycled holders is enough for about 10 rows.
2. **Single `Graph` object, one worker `HandlerThread`.** No dependency-injection framework and no coroutines, so there's nothing to initialise at startup.
3. **`IndexCache` binary snapshot.** The first frame searches the last known index; content providers (contacts, package manager) are re-read in the background afterwards. Aliases are stored in the snapshot too.
4. **Score encoding.** `tier * 100000 + bonus` (bonus < 10000). Kind priority (≤ 180) and pins (500) can reorder results within a tier but never across tiers.
5. **Typo rules.** Edit distance with adjacent swaps, computed only against word *prefixes*. No typos for 1–2 letters, 1 edit for 3–5, 2 edits for 6+. The first letter must match unless the first two letters are swapped. This keeps `gos` → Gouda without filling short queries with junk.
6. **Multi-word queries.** Each query word takes the best unused name word. The score is the *worst* tier among the words, ties broken by the sum of tiers and a small bonus for keeping the order.
7. **Shared aliases.** Alias → items is many-to-many by design (owner asked for "more than one"). An exact alias puts every owner at the top tier.
8. **Transliteration.** A small hand-written Arabic→Latin table with dialect variants (g/j, q/k, vowels) instead of ICU `Any-Latin`: ICU gives academic forms (`ʼsmāʼ`) that don't match how people actually type names. Every variant is indexed.
9. **Autocorrect.** By default `TYPE_TEXT_VARIATION_FILTER | NO_SUGGESTIONS`, which keeps swipe typing and Arabic layouts. The `textVisiblePassword` trick KISS uses is a setting, because some keyboards drop swipe typing or switch to Latin-only with it.
10. **Clipboard.** It only reads `primaryClipDescription` (no toast) and compares its timestamp. `getPrimaryClip()` runs only when the clip is new. No accessibility service, keyboard or Shizuku in v1.
11. **Encryption.** AES-256-GCM with a key in Android Keystore. It protects against backups and file reads, not against someone holding the unlocked phone.
12. **File provider.** A small read-only `ContentProvider` instead of androidx `FileProvider`, to avoid a dependency. It only serves paths under shared storage, and only for read.
13. **File index.** Parallel arrays plus a directory table, persisted in binary and scanned linearly with early cancellation. Memory-mapping and a trigram index are postponed until a real-device benchmark shows the scan misses 30 ms.
14. **minSdk 29.** Settings panels, `isExternalStorageManager` (30), simpler inset code; Android 8–9 is dropped.
15. **No learning from usage.** Ranking is fixed. Users steer it with aliases, pins and the optional "starred contacts as pins".
16. **Widget hosting skipped.** The owner said "the app is just search bar"; hosting other apps' widgets conflicts with that, and doing it well costs a lot. Tacit's *own* search-bar widget is included.
17. **Assistant.** A `VoiceInteractionService` with session and recognition stubs is the minimum needed to appear in the default-assistant list. The session immediately opens the search screen.
19. **Folder grants (SAF).** People who decline All files access can grant folders one at a time through `ACTION_OPEN_DOCUMENT_TREE`. The grants are persisted and walked with `DocumentsContract` queries directly; `DocumentFile` is avoided because it runs one query per file and is much slower. Entries from granted folders store `name + NUL + documentUri` in the same file table, so the matcher and index format stay the same, and opening uses the document URI directly. Grants are kept out of the JSON backup because they don't carry over to another device.
20. **Clipboard lock.** Uses platform `android.hardware.biometrics.BiometricPrompt` with biometric-or-screen-lock (API 30+), or device credential on API 29. `androidx.biometric` isn't used: it's not in the verified version sheet, and the platform API covers minSdk 29. The lock resets on `onStop`, so leaving Tacit locks the clipboard again. FLAG_SECURE stays on while the clipboard scope is visible, locked or not.
21. **Benchmarks.** These live in a separate `:benchmark` module (`com.android.test`) so test code never ends up in the app. A `benchmark` build type mirrors release (R8, shrinking) but is signed with the debug key so it can be installed. Typing cost is measured with a `tacit.query` trace section around each query, plus frame timing for a 30-step script. KISS is compared on cold start only, skipped automatically if KISS isn't installed.
22. **Baseline profile.** `app/src/main/baseline-prof.txt` starts hand-written (startup and search hot paths) and is meant to be replaced by `BaselineProfileGenerator` output from a real phone. AGP compiles it into the APK. Applying it on F-Droid installs needs `androidx.profileinstaller` (pending version confirmation).
23. **Fixtures.** One seeded generator (`sharedTest`) feeds both JVM tests and device tests: 1,000 apps and 3,000 contacts with Arabic, mixed-script and accented names, plus the brief's named examples. Same seed means the numbers are comparable across devices.
18. **Backup disabled.** The clipboard and contacts index must never go to the cloud. JSON export (aliases, snippets, settings) is the way to back up.
24. **Intent stubs in device tests.** `ActivityScenario.close()` starts an `androidx.test` helper activity to bring the app forward. Stubbing `anyIntent()` or `not(isInternal())` also stubs that launch, so every `close()` waited out a 45 s latch. Tests stub through `ExternalIntents.matcher()`, which leaves `androidx.test` components alone. Measured on API 34, 35 and 36 before the fix: launch 117-471 ms, main-thread latency under 5 ms, `close()` 45 s. The search screen's main looper is idle; this was a harness problem, not an app performance problem.
25. **Row holder allocates once.** `ResultAdapter.Holder` builds every view, the selected background, the row ripple, four action buttons with their ripples, and one click listener per kind when the row is first created. `bind()` sets text, toggles visibility and swaps between per-holder cached drawables. `ResultAdapterTest` rebinds a row through every kind three times and fails if a view is replaced or a drawable it has not seen before appears.
26. **Icons are Lucide vector drawables.** 16 icons from the `lucide-static` package are converted to `VectorDrawable` (24 dp, stroke only, round caps and joins, stroke width 1.75) and tinted at runtime by `IconSet`, which keeps one `ConstantState` per resource and hands out `newDrawable().mutate()` copies. No font or icon library is shipped. Licence texts (ISC, plus MIT for the Feather-derived shapes) are in `NOTICE`. WhatsApp and WhatsApp Business icons are compositions of message-circle with phone and briefcase, not brand logos.
27. **Insets frame.** Setting `fitsSystemWindows` on a view replaces that view's own padding with the insets, so Quicklinks, Snippets and Aliases (padding and `fitsSystemWindows` on one view) drew titles and chips on the screen edge. `Ui.screen` wraps the content in a `FrameLayout` that takes the insets, and content keeps its 16 dp padding. `ScreenPaddingTest` checks all four secondary screens.
28. **Mixed-direction text in rows.** Titles, subtitles and the search input use `TEXT_ALIGNMENT_VIEW_START`, so an Arabic name in an English layout (and the reverse) lines up with its neighbours. Subtitles use `TEXT_DIRECTION_FIRST_STRONG_LTR`: with no strong character, such as `+20 100 123 4567` or `~/`, the default falls back to the layout direction and the sign and groups flip in RTL.
29. **Screenshots come from CI.** `ScreenshotTest` sets `wm size 1080x2400` and `wm density 420` (reset afterwards) so captures are phone-sized, plus one capture at the emulator's default 320 dp width. It writes through `screencap` to `/sdcard/tacit-shots` because the per-class uninstall wipes app storage. On `beta`, the API 35 job force-pushes the PNGs to the `ci-screenshots` branch.
30. **Launcher icon.** A prompt chevron and underscore, white on black, drawn with 9.5-unit round-capped strokes on the 108 grid. The chevron's top-left end and the underscore's right end are point-symmetric around the centre and sit on the 66 dp safe circle, so the mark fills the safe zone under circle, squircle and rounded-square masks. Black reads on light and dark wallpapers where the old white tile did not; `icon_background` and `icon_foreground` in `colors.xml` swap it back. The monochrome layer, the Quick Settings tile, the app shortcuts and the widget mark use the same glyph. It replaces a 6 dp stem that was nearly invisible at launcher sizes.
31. **Versions.** One minor per merged milestone with a `-beta` suffix: 0.2.0 is M2, 0.3.0 is M3, and so on up to 1.0.0 at M7; fixes between milestones bump the patch. `versionCode` is `major * 10000 + minor * 100 + patch` (200 for 0.2.0), so every build installs over the last one. The GitHub release tag is the newest file name in `docs/release-notes`, and `RepoRulesTest` fails when no notes file starts with `v` + `versionName`. The seven earlier prereleases (0.1.0-pre.1 to pre.7) keep their names.
32. **Target state.** Every quicklink is OK, MISSING or REPICK. The state is computed when the quicklink source reloads, to label the row, and again at launch. A target that is not OK never launches: Tacit opens the editor on that link. Settings and apps are checked against the live catalog; an app shortcut is only called missing when shortcuts are loaded (Tacit has to be the home app to read them). A path is checked on disk. A `content://` target counts as present only while a persisted read grant covers it, by exact URI or tree prefix, and launching also queries the document, so a file deleted behind a live grant is caught. URIs of Tacit's own file provider need no grant.
33. **Placeholders.** `{query}`, `{clipboard}`, `{date}` and `{date:pattern}` are replaced and URL-encoded one by one. The clipboard is read only when the template contains `{clipboard}`, at launch, and cut at 2000 characters. Any other `{...}` stays as typed. A date pattern `DateTimeFormatter` rejects is refused at save time.
34. **Schemes.** Allowed: http, https, mailto, tel, sms, smsto, geo. Any other scheme is accepted only as `name://...` (an app deep link) and is started with the browsable category. Blocked in every spelling: file, javascript, content, intent, android-app, data, vbscript, about, blob, filesystem, view-source. Deep links are not resolved first: without `QUERY_ALL_PACKAGES` Android hides which apps handle them, so an unhandled link simply does nothing.
35. **Contact actions store the number.** A contact quicklink is `action|number` (call, sms, wa, wab), not a contact lookup key. It keeps working with the Contacts source switched off and without the contacts permission; the cost is that a changed number needs the link edited.
36. **Grants in backups.** Persisted SAF grants do not exist on another device, so export writes an empty target for them and import keeps the name and the label. Those links show "Choose the target again". Import also re-checks every link with the same rules as the editor, so a hand-edited backup cannot bring in `javascript:`, `file:` or a malformed contact action.
37. **Pinned shortcuts.** The shortcut starts a non-exported, history-free `Theme.NoDisplay` activity with only the quicklink id. The target is read, validated and launched at tap time, so editing a link also updates its pinned shortcut and a missing target opens the editor. The icon is a black adaptive bitmap with the white glyph of the link's type.
38. **Picker tests.** Device tests answer `ACTION_OPEN_DOCUMENT` and `ACTION_OPEN_DOCUMENT_TREE` with Espresso-Intents and a URI of Tacit's own provider; the real DocumentsUI is not driven and `requestPinShortcut` is not called (a launcher dialog would take focus). `PinShortcut.info` is checked instead. When Android refuses to keep a picked grant the form says so and keeps the old value.
39. **Alias comparison.** Aliases are compared through the core normalizer (case, accents, Arabic letter variants, collapsed spaces), the same as item names. `AliasRules.clean` drops blanks and duplicates by that key and keeps the first spelling; the store applies it on `set`, `setMany` and load, and the comma/semicolon splitter applies it to typed and imported text, so `Mama, mama` is one alias.
40. **Shared aliases stay legal.** Two items may use the same alias (decision 7). The Aliases screen now names them: `alias: Item, Item`, up to four aliases and three owners each, and items that are no longer indexed are ignored so an uninstalled app does not raise a conflict. Saving an alias from the long-press menu shows a toast naming the other owners.
41. **File aliases.** Files are searched on demand, not indexed, so an alias on a file (key `file:<path or document URI>`) cannot ride the item index. The store keeps a version number; `Graph.aliasedFiles()` rebuilds a list of normalized file aliases only when that number changes, and the search screen matches the typed text against it (exact before prefix, at most 3 rows, above regular results, skipping paths that no longer exist). With no file aliases the check returns before normalizing anything, so typing costs nothing extra.
42. **Alias CSV import** reports how many rows matched no item instead of ignoring them.
43. **Quick actions are plain text rules.** `QuickActions.evaluate` looks at the first word only: an ASCII word of at most nine letters is lower-cased and looked up in one hash map; the normalizer runs only for non-ASCII words (the Arabic keywords). It lives in `core` with no Android types and costs about 0.2 µs per keystroke on the JVM. Rows are built by `ActionRows` through `ComposeInput.actionRows`; nothing runs at startup or per bind.
44. **Row order.** With arguments (`timer 10 tea`, `upper hello`) the action rows come before app matches. A bare keyword (`flip`, `pass`, `event`) goes after the matches when the best match is a word prefix or better, so Flipkart stays above the coin; with no such match it comes first. An exact alias keeps the top slot, as it does for the calculator. Action rows get no alias or pin entries.
45. **Intents, not permissions.** Timer and alarm use the `AlarmClock` intents and need `com.android.alarm.permission.SET_ALARM`, a normal permission granted at install with no prompt. The calendar uses `ACTION_INSERT` on `CalendarContract.Events`, which needs none. `SKIP_UI` is never set, so the clock or calendar app shows what it will create. All-day events carry UTC midnight and an exclusive end one day later, as `CalendarContract` defines; how a calendar app displays that is not verified here.
46. **Dates and times.** Day words: today, tomorrow, weekday names (the next one, never today), `yyyy-mm-dd`, `dd/mm[/yyyy]` day first, and their Arabic words. A time needs a colon or am/pm (`ص`, `م`), so `event meeting 5` keeps the 5 in the title. A time alone means today, or tomorrow once passed; a day alone is an all-day event; default length is one hour. Anything else stays in the title, including impossible dates. No natural-language parser.
47. **Generators.** One `SecureRandom`, created on first use. UUID is version 4 from two random longs with the version and variant bits set. Passwords have 4 to 128 characters, one from each class (no I, O, l, 0, 1), the rest from all classes, then a Fisher-Yates shuffle; they are copied with the clipboard's sensitive flag and kept hidden in history. Dice: 1 to 100 dice with 2 to 1000 sides. `rand` accepts values up to a trillion in either direction with a span up to `Int.MAX_VALUE`.
48. **Transforms.** `upper hello` shows the result and copies it. A keyword alone offers to transform the clipboard: the clipboard is read when the row is activated, never while typing, and the result is copied back. `unb64` and `urldec` accept only valid UTF-8 and show no row otherwise; `urlenc` writes spaces as `%20`.
49. **Contact export.** The destination is picked with `ACTION_CREATE_DOCUMENT`, so Tacit gains no storage access and nothing is sent anywhere. Only phone numbers are read, from the existing READ_CONTACTS permission, on the worker thread after the picker returns, and written row by row through a buffered UTF-8 writer; there is no large string. The result is a toast with the two counts; there is no progress bar. The activity asks for the permission itself when it is missing.
50. **Number and CSV rules.** A number is normalised once: Arabic and Persian digits become ASCII, and spaces, brackets, dots, slashes and dashes go, keeping a leading `+`. A number with anything else (an extension, `*123#`, letters) stays as the contact has it. vCard is 3.0 with CRLF lines folded at 75 octets without splitting a code point, special characters escaped, and no `TYPE` for labels other than mobile, home and work. CSV starts with a UTF-8 BOM, quotes every field and doubles quotes. A leading `=`, `+`, `-`, `@`, tab or carriage return is prefixed with `'`, except for values made only of digits and phone punctuation, which cannot hold a formula, so `+20…` stays a number.
51. **Row size.** Two densities, stored as `density` and part of `Look`, so changing it rebuilds the views like the other look settings. Comfortable (default): 64 dp row, 48 dp icon slot, 40 dp icon bitmaps, 17 sp title, 14 sp subtitle. Compact: 56 dp, 40 dp, 32 dp, 16 sp, 13 sp, the size before 0.5. It follows a look at KISS, whose list is roomier than Tacit's was; the sizes are Tacit's own and the rows keep the same layout. The setting applies to search results and the drawer alike. `RowDensity` holds the numbers in `core` so a test can check they fit.
52. **Drawer is opt-in and apps only.** Off by default (`drawer` in Settings → Look). When on, an Apps button sits beside Settings. The list is every `APP` item in `SearchEngine.all()`, so hidden apps stay hidden, and it is built once per index array when the drawer is first opened (sorted by the first normalized name without leading symbols, ties by label then key). Nothing runs at startup, there is no new package scan or snapshot, and the search screen is unchanged when the switch is off: the extra layout level exists only when the drawer is on. Pinned apps keep their alphabetical place. Contacts, settings and files tabs are left out until a measurement says they are free. A swipe-up gesture is left out for now.
53. **Drawer behaviour.** Opening clears the query, hides the keyboard, lists top to bottom whatever the bar position, and shows no selected row. Typing, tapping the search field, Back, Escape, Home and the Apps button close it and bring the keyboard back; `closeAfterAction` closes it when Tacit stops, so returning from an app lands on search. While it is open focus changes do not raise the keyboard again. An index refresh re-lists the apps in place.
54. **Letter strip.** A 28 dp custom `View` at the end edge (left in RTL) draws one letter per section with no allocation per frame. Touch maps the finger to a section over all letters, so skipped labels (shown only when each cell is at least 15 dp tall) still work; the list jumps with `setSelection` and a bubble shows the letter while touching. Digits and symbols share `#`; Arabic letters form their own sections after Latin. The strip is hidden from accessibility because the list itself scrolls with TalkBack; TalkBack has not been run.
55. **Icon cache.** Entries are keyed by the app key alone. The cache empties when the icon mode, dark mode or row size changes, and a generation number makes renders that finish after such a change drop their result; before this, every bind built a key string. The worker also skips a render when the row has been bound to another app by the time it gets there, which keeps a fast fling through a long list from queuing icons nobody sees. Bitmaps follow the row size (40 dp comfortable, 32 dp compact) and the cache grows from 8 to 12 MB so about 200 comfortable icons stay warm. The new Apps icon is Lucide `layout-grid`.
56. **Settings tab.** The drawer can show a second tab, System settings, switched on in Settings → Look under the drawer switch (`drawer_settings`, off by default). With it off the layout has no tab row and the code path is the Apps-only one from 0.5. With it on, the tab list is built the first time the tab is opened, from the `SETTING` items already in `SearchEngine.all()`, and cached with the apps list for as long as the index array is the same one. It reuses the rows, letter strip, long-press menu and tap behaviour of search, so a toggle such as Flashlight still toggles in place. No scan, snapshot or startup work is added.
57. **What the tab leaves out.** The three rows made for every installed app (`appinfo:`, `appnotif:`, `appprefs:`) are not listed: they would be three times as long as the apps list and the same screens are one long-press away on the app. `DrawerTab.accepts` holds the rule so a test can check it. The tab choice lasts while the search screen lives; opening the drawer again shows the tab last used, and a rebuilt screen starts on Apps.
58. **Files tab not built.** The plan allowed a files tab only if it costs nothing at launch. Files are searched on demand rather than indexed in memory, so a list would need a scan of its own, and a scan that is still running reads to a new user as "not found". That belongs with the file-scan work (speed and a visible scanning state) listed in `docs/HANDOFF.md`, not with this tab.
59. **First-run card.** One outlined card laid over the list area (at the bottom when the bar is at the bottom, otherwise at the top), not a separate screen, so the field and keyboard work at once and the search bar is never covered or pushed off in landscape. It says what Tacit searches, that contacts, files and clipboard are off until switched on, and that Tacit has no internet access. "Make it my home" opens the platform's home-app settings and is left out when Tacit already is the home app; "Got it" hides the card. Typing, opening the drawer and leaving the screen also end it, so it shows once per install.
60. **Seen state is a marker file.** `Welcome` checks for an empty file `welcomed` in `filesDir` once per process (one `File.exists()`, cached) and creates it on the worker thread when the card ends. It is not a preference because four device test classes clear the preferences. `TacitTestRunner` creates the file before any test starts, so every class except `FirstRunTest` runs without the card; `FirstRunTest` deletes it and puts it back. Nothing is added to `Application.onCreate`, and after the first run the cost is one boolean read. The first benchmark iteration after a reinstall includes the card; the median does not. Beta testers see the card once on 1.0.0, which they have to reinstall anyway because the stable release is signed with a different key.
61. **CI does not sign.** A stable release is a notes file whose name has no suffix (`v1.0.0.md`). CI then creates a draft release holding the unsigned release APK and `SHA256SUMS`, and the owner signs outside GitHub (`tools/sign-release.sh` or three commands, `docs/SIGNING.md`) and uploads the result. Beta notes keep publishing a prerelease with the debug APK. An existing release is only given refreshed notes; assets the owner uploaded are never touched. Releases are looked up through the REST list, not by tag, because a draft has no tag yet and the tag lookup does not return drafts. `RepoRulesTest.signingKeysNeverEnterTheRepoOrTheWorkflow` fails on key files, signing words in `build.gradle.kts`, `secrets.` in the workflow, or a `.gitignore` without the key patterns.
62. **CI proves the tooling, not a key.** Every run makes a throwaway PKCS12 key on the runner, signs the unsigned release APK with `tools/sign-release.sh` and throws both away, so a broken script or an unsignable APK shows up before the owner needs it. A second `assembleRelease --rerun-tasks` is compared byte for byte with the first and the result is a notice, not a failure: F-Droid can only publish the owner's signature when its own build matches, and a build that already differs on one runner cannot. The notice also lists a fingerprint per APK group. Across two runners building the same source, only `META-INF/version-control-info.textproto` differed (AGP writes the git commit there; the pull request run builds a merge commit, the push run the pushed one). Code, resources, manifest, baseline profile, entry order and timestamps matched. So the release APK is repeatable for a given commit, which is why the draft release is built from the commit that becomes the tag. Whether F-Droid's builder reproduces it is not tested.
63. **F-Droid.** Listing text lives in `fastlane/metadata/android/en-US` and `ar` (title, short and full description, one changelog per `versionCode`); `RepoRulesTest` checks the lengths and that the changelog for the current version exists in both. `docs/fdroid/app.tacit.yml` is a draft recipe with `Binaries` pointing at the owner-signed `tacit-v%v.apk` release asset. It is not validated, because F-Droid's tools are not available here, and the signing fingerprint is a placeholder. No screenshots are shipped: the CI captures are emulator images from earlier builds, so real phone screenshots are left to the owner.
64. **Licence.** GPL-3.0 only: the FSF text unchanged in `LICENSE`, `GPL-3.0-only` in the F-Droid recipe, and the existing "GPL-3.0" line in Settings. Lucide icons keep their own ISC and MIT notices in `NOTICE`. Source files carry no licence headers (the no-comment rule); `LICENSE` at the root covers them. Changing to "or later" means editing the recipe line and saying so in the README.
65. **Versions for 1.1.** Patch betas, then a clean minor: M8 is 1.0.1-beta (10001), M9 1.0.2-beta, M10 1.0.3-beta, M11 1.0.4-beta, M12 1.0.5-beta, and M13 is 1.1.0 (10100). Taking the next minor for each beta, as decision 31 did before 1.0.0, would leave the stable release with a `versionCode` no higher than the last beta, and a phone would refuse to install it over that beta. The formula `major * 10000 + minor * 100 + patch` is unchanged. Every milestone adds `docs/release-notes/v<versionName>.md` and a changelog of at most 500 bytes per `versionCode` in `en-US` and `ar`.
66. **Guard script and protected files.** `.github/scripts/guard-check.sh` is the first step of the `build` job (checkout uses `fetch-depth: 0`) and compares `HEAD` with `git merge-base origin/main HEAD`. It fails when the number of `@Test` lines under `app/src/test`, `app/src/androidTest` and `app/src/sharedTest` is lower than at the base, and when a line added to a `.kt` file carries `Ignore`, `Assume.` or an `assume*` call. The pattern is wider than `@Ignore`: a first version let `@org.junit.Ignore` through, so every qualified spelling is matched now. It prints a warning that lists the protected paths a change touches (workflows and scripts, `RepoRulesTest`, `KeystrokeBudgetTest`, `Budgets.kt`, the golden files, `app/build.gradle.kts`, `proguard-rules.pro`, the manifest, `lint-baseline.xml`); a pull request names them under "Guard changes". It cannot stop an owner-level push, since `main` is not protected on the repository, so the agent rules in the plan cover that part. On `main` the script does nothing.
67. **Golden tests.** `RankingGoldenTest` records `SearchEngine.search(q, 8)` for 109 queries over `Fixtures.all()` and the `ResultComposer` output for 35 more (calculator, typed actions, phone, URL, email, web and prefix scopes, a quicklink row) in `golden/ranking.tsv`. `FileGoldenTest` records the top 10 `path@score` of `FileMatcher.search` for 100 queries on a 50,000-entry table from `FileFixtures` (`Random(42)`, English and Arabic words, 30 extensions, depth 1 to 6, about 8% folders, three years of modified times) in `golden/files.tsv`. Both compare exact keys, order and scores. A mismatch writes `app/build/golden-actual/<name>` and puts the full actual text in the failure message; CI also prints it as `Golden actual` annotations: the file compressed with `xz`, base64 encoded and cut into parts of 3,500 characters (an annotation is cut at about 4,000), with the sha256 of the original in each title. A golden file changes only with the owner's approval, never to turn CI green. To regenerate one: empty the file, push, rebuild the text from the annotations, check the sha256, commit it as its own commit and list it under "Guard changes". `ranking.tsv` was generated before any `app/src/main` change. `files.tsv` was generated from the unchanged matcher too: the fixture takes the clock as an argument and keeps every age at least an hour from a day boundary, so the unchanged matcher gave the same scores on the wall clock as the injected `now` gives on the fixed `FileFixtures.NOW`, which is what the later green run shows. The injectable `now` (default `System.currentTimeMillis()`, placed before the `cancelled` lambda so every call site compiles) is the only change under `app/src/main` in M8; it is read once per search instead of once per candidate, which can differ only when a search straddles midnight.
68. **Lint baseline.** `lint` runs with `abortOnError = true`, `warningsAsErrors = false`, `checkReleaseBuilds = false` and `baseline = app/lint-baseline.xml`, so a new lint error fails `lintDebug` while the 20 findings that already existed (four `InlinedApi` on API 30 constants, three `PluralsCandidate`, two `UnusedAttribute` in the widget info, `GestureBackNavigation`, `OldTargetApi`, `SdCardPath`, `DiscouragedApi` on the fixed orientation, `ExportedService`, `DataExtractionRules`, `ViewConstructor`, `ByteOrderMark` in `ContactFormats.kt`, `SetTextI18n`, `RtlSymmetry`, `AndroidGradlePluginVersion`) stay listed but do not fail anything. It is a warning that fixing them is not part of M8, nothing more: `ExportedService` and `OldTargetApi` are worth a look in a later milestone. The file was written by `updateLintBaseline` on the unchanged sources in a temporary dispatch job, and rebuilt from that job's annotations (sha256 `a7f13d718df1e3a00c762b42af4d1f1977ce2e104bab0691ed9b7283c4d2c3bc`) because an artifact cannot be downloaded from the build environment. `AndroidGradlePluginVersion` names the newest Gradle, so a later Gradle release can show it again as a new warning; warnings never fail the gate. `app/lint-baseline.xml` is a protected file: shrinking it is fine, growing it needs the owner.
69. **StrictMode trend and idle waits in tests.** `TacitTestRunner` sets a thread policy (disk reads, disk writes, network, log) and a VM policy (leaked closables, leaked activities, log) in `callApplicationOnCreate`, before `TacitApp.onCreate`, so the main-thread work of every process start is counted too. `device-tests.sh` now keeps the logcat of every test class (one `adb logcat -d` per class, then `-c`, because a single dump at the end lost lines to the ring buffer), counts `StrictMode policy violation` and counts again the ones with an `app.tacit` frame, and puts both numbers and the ten most frequent `app.tacit` frames first in the summary notice. The counts of the M8 run per API level are in `docs/strictmode-baseline.txt`; later milestones should not raise them. It is a report, not a failure. The most frequent frames are `SearchActivity.onCreate`, `SettingsActivity.build` and `onResume`, `Graph.init` inside `TacitApp.onCreate`, `Prefs.<init>`, `Welcome.pending` and `SearchActivity.buildViews`: all main-thread disk reads. B22 (`SettingsApplyTest` flakes): ten isolated runs of the class on an API 35 emulator all passed, so the cause was not reproduced and is not claimed. From the code, the places where a test could assert before the app had settled are the return to the resumed state after a preference change (`onResume` rebuilds the views, and a theme change calls `recreate()`), the preference reset between tests that touches `Graph.applyPrefs()` while the worker may still be rebuilding, and the way back from Settings. `Idle.await()` posts a latch to `Graph.worker`, then one to `Graph.main` once the worker's has run, and waits at most five seconds in total; on a timeout it logs and lets the test's own assertion decide. `SettingsApplyTest` calls it after each return to resumed, after leaving Settings and around the preference reset. A different test of the same family failed once on API 34 in the M8 branch (`ActionsTest.aBareKeywordWaitsBehindARealApp` saw real device rows, an Airplane mode setting and no Flipkart, instead of the injected items), and that one has a cause in the code: `Graph.init` posts a task that replaces the engine's items with the cached index and then runs `refreshAll()`, `useItemsForTesting(null)` queues another `refreshAll()`, and `rebuild()` reads `overrideItems` once, so a task still running when the next `setUp` injects items can put the real items back. The startup replacement does not look at `overrideItems` at all. Tests cannot change that in M8, so every class that injects items (`ActionsTest`, `AliasesTest`, `DrawerTest`, `QuicklinksTest`, `QuicklinksV2Test`, `ScreenshotTest`, `SearchScreenTest`) now calls `Idle.await()` before installing items in `setUp` and after clearing them in `tearDown`. This is a plausible cause of the old pattern of a different test failing each time and passing on re-run; for `SettingsApplyTest`, which injects no items, it is not shown. No assertion changed, and there is no sleep or retry. If a flake comes back, the `TacitIdle` lines in logcat will say whether an idle wait ran out; the refresh and rebuild paths belong to the M9 work on `Graph`.
70. **Refresh coalescing and source masks (B06).** `Graph.requestRefresh(sources)` takes a bit mask: APPS 1, CONTACTS 2, SETTINGS 4, SNIPPETS 8, QUICKLINKS 16, ALL 31, and no argument means ALL. `RefreshCoalescer` (in `core/`, scheduler injected, unit-tested) keeps the pending bits in an `AtomicInteger`; the first request, the one that moves it from 0, schedules a flush 400 ms later on the worker, which takes the bits with `getAndSet(0)`, reloads only those sources and rebuilds once. Fifty requests in a burst give one run with the union of the bits. Settings depend on apps, so APPS always adds SETTINGS. Package callbacks request APPS and the contacts observer CONTACTS. Three things read from this. Icon eviction (B07): the callback bumps `Graph.packagesVersion`, posts `IconCache.evictPackage` to the main thread, and the cache remembers the package of every key it holds, so an updated app loses only its own icon. Messenger buttons (B08): `SearchActivity` remembers the last `packagesVersion` and re-reads WhatsApp and WhatsApp Business on resume and whenever the index refreshes, but only when it changed. Aliased files (B09): a map of key to "exists" is rebuilt on the worker when the alias version changes or the screen resumes, and the keystroke path reads the map instead of the disk. Unknown keys count as present until the worker has built the map, so a deleted aliased file can show for a few milliseconds after a cold start (it hides on the next query); the deleted-file test in `AliasesTest` now waits with `Idle.await()` before it asserts, with the same assertions. `Idle.await()` calls `Graph.flushRefresh()` first, which runs a pending coalesced refresh at once, so tests do not wait 400 ms or sleep. `refreshAll()` and `useItemsForTesting(null)` still run immediately. Not included: the dedicated icon thread, which is M13.
71. **IndexCache v4 (B05, B25).** The format moved to `core/IndexCodec` over `DataInput` and `DataOutput`, so a JVM test can round-trip it; `IndexCache` only picks the file (`cache/index.bin`) and swallows errors. `VERSION` is 4 and any other version, a short file or a bad marker reads as null, which is the same fallback as no cache. That is why there is no migration: the file is a rebuildable cache that the refresh at start rewrites, never user data. Per item: key, kind, label and subtitle (cut at 4,000 characters), the payload as a length and UTF-8 bytes with no cut (a long snippet copied before the first refresh used to lose everything past 16,000 characters), the pinned flag, up to 64 extra names (1,000 characters each) and 64 aliases (200 each), and one marker byte: 0 nothing, 1 contact, 2 quicklink type. A contact keeps its lookup key, id, numbers, primary number, both WhatsApp data ids (-1 for none) and the starred flag, so the contact buttons and the WhatsApp choice work from the cached frame; before this they appeared only after the first refresh. A quicklink row keeps its type name for the row icon, and a name this build does not know reads as null. Guards against a damaged file: at most 5,000,000 items, 64 MiB for one payload and 1,000 numbers for one contact.
72. **Clip thread, and other work moved off the main thread.** `ClipboardStore` starts a `tacit-clip` thread on its first post (never in `onCreate`) and runs the capture on window focus and its 600 ms retry there, so a busy worker (index read, refresh, rebuild) cannot delay a read that Android allows only while Tacit has focus. The store was already synchronized. Also off the main thread now: the crash report check (read once on the worker at start into `Graph.crashReportSaved`; the file is written only by the crash handler just before the process ends, so the answer holds for the whole process; no test, because it would need a process restart), writing a backup to the chosen file (`BackupCompatTest.exportWritesTheBackupToThePickedFile`), and importing one (B16): the file is read on the worker and summarized by `Backup.summarize`, a dialog shows the aliases, snippets and quicklinks it holds, and only a confirmed import runs `Backup.import` on the worker, then on the main thread `applyPrefs`, an icon cache clear, a full refresh, and `recreate()` if the theme changed, otherwise `build()`. A file that is not a Tacit backup shows a message and changes nothing. Smaller choices: `ResultAdapter.getItemId` returns the position and `hasStableIds` is false (B18; the list view calls `getItemId` even for an empty adapter when it restores a selection, so declaring stable ids was never safe, and key hashes collide: `Aa` and `BB`); `submit(items, selected)` assigns both and notifies once, and `publish()` reads the bar position from `look` (B10); a pinned shortcut follows a quicklink's rename or type change with `updateShortcuts`, and a deleted quicklink disables it with the message "This quicklink was deleted" (B15); the hidden items dialog shows labels from every source, and an item that is no longer indexed shows its key without the prefix and path, `com.example.mail` for `app:com.example.mail` (B17); `isDefaultHome()` is cached until the next `onResume` (B27, no test: the saving is one PackageManager call per Back press and counting calls would need test-only hooks); the normalizer compiles its camel-case regex once and returns `lowercase()` for pure ASCII input (B04, checked against a copy of the 1.0.0 algorithm on every fixture name and 10,000 random strings). Main-thread disk work that is left: `Prefs` loads inside `Graph.init`, `Welcome.pending` checks its marker once per process, and the quicklink editor saves, deletes and rechecks targets on the main thread, because the stores write their files synchronously and several device tests read them straight after the click; moving the editor needs an asynchronous store API first.
73. **File index threads, generations and scan state (B02, B12, B23).** `FileIndex` owns two lazy threads: `tacit-files-scan` at background priority for scans and header reads, and `tacit-files-search` at default priority for queries and for loading `files.bin`, so a scan never delays a keystroke. The old single thread did both and an exception in a scan left `indexing` true for the rest of the process. A scan now runs in try, catch and finally: a failure goes to `Graph.recordFailure`, which writes `last_crash.txt` through the same `CrashLog.write` as the crash handler and keeps the old table, and the `queued` and `running` flags are reset in `finally`. A scan generation (`AtomicInteger`) is bumped when a scan starts, by `clear()` and by a request that arrives during a scan; `TableBuilder` checks it every 1,024 entries and stops, and a table or a state is published only under `publishLock` while the generation is still the one that scan took, so a cancelled scan can never publish after `clear()`. `clear()` sets the empty table at once and deletes `files.bin` on the scan thread, behind any scan that is finishing. Requests coalesce: `rescan(done)` merges while a scan is queued, a request during a scan cancels it and runs one more scan, every callback runs after the last one, and `maybeRefresh()` is dropped while a scan is queued or running (B23). `ScanState` is Idle, Scanning(found, startedAt) or Done(count, at, truncated), kept in a volatile field; listeners are added and removed on the main thread, are posted there, and always receive the current state, so two threads cannot deliver an old state last. `found` is reported at most every 250 ms. Partial results: when no table is loaded and `files.bin` does not exist, a snapshot of the entries so far becomes the served table every 25,000 entries, or every 250 ms when there are new entries, where the time trigger waits at least four times as long as the previous snapshot took, so copying stays a small part of the scan; a refresh keeps serving the old table until the new one is ready (B01). The search screen shows the "Indexing files… N found" row in the Files scope while a scan runs and in the All scope only after the file search has answered with no hits, shows a "not indexed" row in the Files scope when files are on, nothing is indexed and there is no access, re-runs the file query at most every 500 ms while it has no results and once when a scan ends, and starts `preload()` on resume so the first keystroke does not read `files.bin`. After a restart `summarize()` reads only the header, so Settings shows the real count (B03: it showed 0 until the first search). Not done: no foreground service, so Android can end the process during a very long first scan; the next resume sees no file and starts again.
74. **File scan strategies, and the measured choice.** `ScanStrategy` has four implementations behind one sink, `TableBuilder` (`FileWalkStrategy`, the 1.0.0 walker kept as the baseline; `NioWalkStrategy`; `MediaStoreStrategy`; `TreeStrategy` for chosen folders). The emulator benchmark (`FileScanBenchmarkTest`, Android 15, x86_64, 30,300 seeded files and 3,000 folders, including a `.nomedia` folder with 200 files, a hidden folder with 100, and 50 files created seconds earlier) gave, best of three rounds on three CI runs, 33,333 entries: File walker 932, 1,341 and 1,793 ms, NIO walker 862, 1,347 and 1,849 ms, MediaStore 183, 278 and 347 ms (runners differ; on each run MediaStore took about a fifth of the walkers' time). The sets are identical in all four directions: the two walkers agree, and MediaStore finds everything the walkers find, including the `.nomedia` files, the 50 fresh files (all 50 at once, before any media scan) and the 100 hidden files when it is asked to include them. MediaStore lists folders as rows without a MIME type; the first version turned them into files, and the strategy now turns them into folders (with the folder's own date) and adds the folders above every file. The rule from the plan applies: because MediaStore covers everything the walker finds, it is the default with All files access, and a walk runs at most once every 24 hours. Concretely: the first scan runs MediaStore, publishes it, then runs the walker and replaces the table; an automatic refresh runs MediaStore alone and the walker alone when the last walk (`verifiedAt` in the header) is more than 24 hours old, and the Rescan button always walks, because a user who asks for a rescan expects the disk to be read (a refresh with an old table runs one phase, so the old table keeps serving until the new one is ready); the strategy that built a table is recorded in the header, and `RefreshPolicy.phases` makes the choice as a pure function with its own tests. The NIO walker is not faster than the File walker on the emulator (862 against 932 ms on the quickest run, 1,347 against 1,341 ms on another, within the noise between rounds); it is the one the app uses because it does not follow symbolic links, so a link cycle cannot loop, and it reads one set of attributes per entry instead of three calls. Without All files access, Android 10 with the read permission uses the NIO walker and chosen folders use `TreeStrategy`, which is slower because Android answers one query per folder (in `limits.md`). The emulator is not a phone: a phone whose MediaStore misses files that apps write behind its back is covered by the daily walk, and the benchmark prints the per-category differences (`TACIT_FILESCAN`) so a phone run shows them. The benchmark asserts only that the two walkers agree, because a MediaStore difference is information, not a failure.
75. **When the file index refreshes (B01).** `FileIndex.maybeRefresh()` runs from `onResume` of `SearchActivity` and `SettingsActivity`, never from `onCreate`, posts to the scan thread and does nothing when files are off, there is no access, or a scan is queued or running. `RefreshPolicy.shouldRefresh` decides on what is stored in the header: no readable header (no file, a version 1 file, a damaged file) means scan, unless a scan finished in the last 120 seconds (so a full disk cannot start a scan on every resume); with All files access the version and generation that MediaStore reports for each volume are compared with the stored ones and a difference means scan, again only when the last scan finished more than 120 seconds ago; with chosen folders, or without MediaStore, a scan runs when the index is older than six hours. The stamps are read before a scan begins, so a change made during the scan starts another on the next resume. Why not `FileObserver`: it watches one folder and not its children, a phone has tens of thousands of folders against an inotify limit shared with every app, each watch holds kernel memory, and events are lost on overflow and while the process is not running; one `getGeneration` call per volume answers the same question when the user looks at the screen. Why not a scheduled job: it needs background work or a foreground service and its battery cost for an index that matters only while the screen is on. The cost of this choice: a change that reaches storage without reaching MediaStore (chosen-folder mode, or a file written behind the media provider) waits for the next walk, at most 24 hours with All files access and six hours otherwise, and Rescan is always there.
76. **File index format 2 (B03, B11).** The file starts with the magic `0x54464932` and version 2, then the header: entry count, time created, time of the last walk (`verifiedAt`, an addition to the plan's header so that decision 74's daily walk survives a restart), the strategy that built it, a truncated flag, and per MediaStore volume the name, version string and generation. Then the directory list, then the entries: name (a folder without its trailing slash), a flags byte (1 the normalized name is stored, 2 folder, 4 has a document URI), the normalized name only when it differs from `name.lowercase()`, the document URI when flagged, the directory index, the size and the time. Plain names cost no normalized copy in the file or in memory (the table shares the string), and loading skips the normalizer for them; the file is about 10% larger than version 1 on the 20,000-entry fixture because of the flags byte and the stored form of non-ASCII names. Chosen-folder entries keep their document URI for folders as well as files, so `FileTable.pathOf` returns a `content://` URI for both and `Actions.openFile` sends a directory document to the folder opener (B11: a folder hit used to open nothing, because its path was a `tree:` key). The reader refuses what could crash a search later: an entry count above 500,000, a directory count above 2,000,000, a volume count above 64, and a directory index outside the list. Migration: a version 1 file is read by the old layout reader (normalized names are recomputed) and has no header, so `maybeRefresh()` sees no readable header and scans once; the new file replaces it. There is no separate migration pass because the file is a rebuildable cache, as with decision 71, and the old file keeps serving until the new one is written. `FileIndexMigrationTest` covers a version 1 file read into a correct table, a version 2 round trip with chosen-folder files and folders and Arabic names, a header-only read, an unknown file, and the two rejections.
77. **File matcher speed without changing results (B13).** Each table entry has a 64-bit mask of the characters in its normalized name: bits 0 to 25 for a to z, 26 to 35 for 0 to 9, and 36 plus the character code modulo 28 for anything else. A query's mask is the union of the characters of its terms (after an implicit extension such as the `pdf` in `report pdf` has been taken out) and an entry is skipped unless it has every one of those bits. A term that occurs in a name has all its characters in the name, so the mask can only let extra entries through and never drops one; the scorer still decides. The mask costs 8 bytes per entry (4 MB at the 500,000 limit) and is computed when the table is built (incrementally in `TableBuilder`) or read. Also changed: the `.extension` suffix is built once per search instead of once per entry, the `in:` filter is resolved once per directory into a boolean array instead of a string search per entry, and the base-name test uses `lastIndexOf` and `regionMatches` instead of allocating a substring. Results are identical: `FileMatcherEquivalenceTest` compares the new matcher with `LegacyFileMatcher`, a copy of the 1.0.0 code in the test sources, on 300 generated queries (single words, fragments, one and two characters, two and three terms, `ext:`, `*.`, `in:`, an implicit extension, capital letters, Arabic words, no match) over 300,000 entries, for limits 1, 10 and 25, and `FileGoldenTest` and its golden file are unchanged. Speed: `FileSearchSpeedTest` runs 60 queries over 200,000 entries in five interleaved rounds after two warm-up rounds and asserts that the new median is at most 0.6 times the 1.0.0 median; on CI it was 95 to 114 ms against 375 to 476 ms (about a quarter), locally 88 against 350 ms. The per-query latency on the same fixture prints as `TACIT_FILESEARCH_JVM` (CI: p50 about 1.2 ms, p95 about 5 to 6 ms; one runner is noisier than another, so no budget is set here and the owner adds one to `Budgets.kt` after a phone run). The mask helps least for one-character queries and for queries made of the commonest letters, where most entries pass; those cost what they did before.
