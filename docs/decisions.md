# Decisions

The code has no comments (owner's rule). This file explains why things are the way they are.

1. **Plain `Activity` and platform widgets.** No AppCompat, Compose or RecyclerView: zero runtime dependencies means less class loading at cold start and a smaller heap, so Android kills the process less often. `ListView` with recycled holders is enough for about 10 rows.
2. **Single `Graph` object, one worker `HandlerThread`.** No dependency-injection framework and no coroutines, so there's nothing to initialise at startup.
3. **`IndexCache` binary snapshot.** The first frame searches the last known index; content providers (contacts, package manager) are re-read in the background afterwards. Aliases are stored in the snapshot too.
4. **Score encoding.** `tier * 100000 + bonus` (bonus < 10000). Kind priority (≤ 180) and pins (500) can reorder results within a tier but never across tiers.
5. **Typo rules.** Edit distance with adjacent swaps, computed only against word *prefixes*. No typos for 1–2 letters, 1 edit for 3–5, 2 edits for 6+. The first letter must match unless the first two letters are swapped. This keeps `gos` → Gouda without filling short queries with junk.
6. **Multi-word queries.** Each query word takes the best unused name word. The score is the *worst* tier among the words, ties broken by the sum of tiers and a small bonus for keeping the order.
7. **Shared aliases.** Alias → items is many-to-many by design (owner asked for "more than one"). An exact alias puts every owner at the top tier.
8. **Transliteration.** A small hand-written Arabic→Latin table with dialect variants (g/j, q/k, vowels) instead of ICU `Any-Latin`: ICU gives academic forms (`ʼsmāʼ`) that don't match how people actually type names. Every variant is indexed.
9. **Autocorrect.** By default `TYPE_TEXT_VARIATION_FILTER | NO_SUGGESTIONS`, which keeps swipe typing and Arabic layouts. The `textVisiblePassword` trick KISS uses is a setting, because some keyboards drop swipe typing or switch to Latin-only with it.
10. **Clipboard.** It only reads `primaryClipDescription` (no toast) and compares its timestamp. `getPrimaryClip()` runs only when the clip is new. No accessibility service, keyboard or Shizuku in v1.
11. **Encryption.** AES-256-GCM with a key in Android Keystore. It protects against backups and file reads, not against someone holding the unlocked phone.
12. **File provider.** A small read-only `ContentProvider` instead of androidx `FileProvider`, to avoid a dependency. It only serves paths under shared storage, and only for read.
13. **File index.** Parallel arrays plus a directory table, persisted in binary and scanned linearly with early cancellation. Memory-mapping and a trigram index are postponed until a real-device benchmark shows the scan misses 30 ms.
14. **minSdk 29.** Settings panels, `isExternalStorageManager` (30), simpler inset code; Android 8–9 is dropped.
15. **No learning from usage.** Ranking is fixed. Users steer it with aliases, pins and the optional "starred contacts as pins".
16. **Widget hosting skipped.** The owner said "the app is just search bar"; hosting other apps' widgets conflicts with that, and doing it well costs a lot. Tacit's *own* search-bar widget is included.
17. **Assistant.** A `VoiceInteractionService` with session and recognition stubs is the minimum needed to appear in the default-assistant list. The session immediately opens the search screen.
19. **Folder grants (SAF).** People who decline All files access can grant folders one at a time through `ACTION_OPEN_DOCUMENT_TREE`. The grants are persisted and walked with `DocumentsContract` queries directly; `DocumentFile` is avoided because it runs one query per file and is much slower. Entries from granted folders store `name + NUL + documentUri` in the same file table, so the matcher and index format stay the same, and opening uses the document URI directly. Grants are kept out of the JSON backup because they don't carry over to another device.
20. **Clipboard lock.** Uses platform `android.hardware.biometrics.BiometricPrompt` with biometric-or-screen-lock (API 30+), or device credential on API 29. `androidx.biometric` isn't used: it's not in the verified version sheet, and the platform API covers minSdk 29. The lock resets on `onStop`, so leaving Tacit locks the clipboard again. FLAG_SECURE stays on while the clipboard scope is visible, locked or not.
21. **Benchmarks.** These live in a separate `:benchmark` module (`com.android.test`) so test code never ends up in the app. A `benchmark` build type mirrors release (R8, shrinking) but is signed with the debug key so it can be installed. Typing cost is measured with a `tacit.query` trace section around each query, plus frame timing for a 30-step script. KISS is compared on cold start only, skipped automatically if KISS isn't installed.
22. **Baseline profile.** `app/src/main/baseline-prof.txt` starts hand-written (startup and search hot paths) and is meant to be replaced by `BaselineProfileGenerator` output from a real phone. AGP compiles it into the APK. Applying it on F-Droid installs needs `androidx.profileinstaller` (pending version confirmation).
23. **Fixtures.** One seeded generator (`sharedTest`) feeds both JVM tests and device tests: 1,000 apps and 3,000 contacts with Arabic, mixed-script and accented names, plus the brief's named examples. Same seed means the numbers are comparable across devices.
18. **Backup disabled.** The clipboard and contacts index must never go to the cloud. JSON export (aliases, snippets, settings) is the way to back up.
24. **Intent stubs in device tests.** `ActivityScenario.close()` starts an `androidx.test` helper activity to bring the app forward. Stubbing `anyIntent()` or `not(isInternal())` also stubs that launch, so every `close()` waited out a 45 s latch. Tests stub through `ExternalIntents.matcher()`, which leaves `androidx.test` components alone. Measured on API 34, 35 and 36 before the fix: launch 117-471 ms, main-thread latency under 5 ms, `close()` 45 s. The search screen's main looper is idle; this was a harness problem, not an app performance problem.
